# پیکربندی Claude Code در این مخزن

> این پوشه کاری است که Claude Code وقتی **در ریشهٔ همین مخزن** اجرا شود
> می‌بیند. همه چیز اینجا تولیدشده است؛ دستی ویرایش نکنید.

## چرا repo-local؟

فهرست عامل‌ها همراه مخزن سفر می‌کند: هر کسی که `git clone` کند و
`./scripts/install.sh` بزند دقیقاً همان ۴۸ عامل را دارد. وابستگی به تنظیمات
شخصی ماشین صفر است.

اگر نسخهٔ سراسری هم می‌خواهید:

```bash
./scripts/install.sh --user    # ~/.claude/agents/ (فقط همین ماشین)
```

## چه چیزی اینجاست

| فایل/پوشه | ماهیت | چه چیزی می‌سازد |
| --- | --- | --- |
| `agents/` | تولیدشده | ۴۸ فایل عاملی، کپی بایت‌به‌بایت از `upstream/` |
| `AGENCY-ROSTER.md` | تولیدشده | نگاشت بخش کارن‌سافت ↔ شناسهٔ نصب‌شده |
| `README.md` | دستی | همین فایل |

## قاعدهٔ نگه‌داری

`agents/` را **دستی ویرایش نکنید**. سه راه درست برای تغییر رفتار:

1. قاعدهٔ تیم را در `departments/<بخش>/README.md` بنویسید؛
2. ورودی/خروجی/شرط پذیرش را در `workflows/` دقیق‌تر کنید؛
3. عاملی از بالا دست اضافه کنید (سطر جدید در `agents/registry.tsv`).

برای بازنویسی:

```bash
./scripts/install.sh --force
./scripts/install.sh --check
```

## چطور Claude Code این‌ها را می‌بیند

- هر فایل `agents/*.md` یک **subagent** است که با `name:` داخل فرانت‌متر
  شناسایی می‌شود، نه با نام فایل.
- شناسه‌ها همان شناسهٔ بالا دست‌اند (`engineering-sre`، `security-penetration-tester`)
  تا نصب ابزارهای دیگر و ارتقا بدون نقشه‌برداری دستی کار کند.
- نام فایل در `agents/<بخش>/` کوتاه‌تر است (`sre`، `penetration-tester`).
  جدول کامل: `.claude/AGENCY-ROSTER.md`.

## محدودیت‌ها

- این فایل‌ها **حالت گفت‌وگو** Claude Code را تغییر نمی‌دهند؛ فقط فهرست
  subagentها را اضافه می‌کنند.
- Claude Code باید از ریشهٔ مخزن اجرا شود، وگرنه `.claude/agents/` را نمی‌بیند.
- نصب پوشهٔ مخفی `.claude` را در گیت نگه می‌داریم چون عمداً repo-local است؛
  اگر آن را نمی‌خواهید، `./scripts/install.sh --user` بزنید و این پوشه را
  `.gitignore` کنید.
