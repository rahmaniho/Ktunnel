# آژانس هوش مصنوعی کارن‌سافت

> **KarenSoft AI Agency** — یک لایهٔ هماهنگی روی مجموعهٔ متن‌باز
> [agency-agents](https://github.com/msitarzewski/agency-agents) که ۴۸ متخصص
> منتخب را به یک خط تولید با مالک، قرارداد، و دروازهٔ کیفیت تبدیل می‌کند.

[![check](https://github.com/rahmaniho/Ktunnel/actions/workflows/check.yml/badge.svg)](../../actions/workflows/check.yml)

## در یک نگاه

| | |
| --- | --- |
| عامل‌ها | ۴۸ متخصص منتخب از ۲۸۳ عامل بالادست |
| بخش‌ها | ۶ بخش: اجرایی، مهندسی، طراحی، امنیت، کیفیت، بازاریابی |
| جریان‌های کاری | ۵ جریان: پروژهٔ جدید، توسعهٔ قابلیت، بررسی باگ، حسابرسی امنیتی، انتشار |
| دروازه‌ها | ۶ دروازه از G0 (دامنه) تا G5 (پذیرش) |
| نصب | repo-local در `.claude/agents/` — همراه مخزن، برای همهٔ اعضای تیم |
| زبان | مستندات فارسی؛ متن عامل‌ها انگلیسی (بدون تغییر از بالادست) |

## شروع سریع

```bash
# ۱. بررسی سلامت مخزن (بدون شبکه)
./scripts/check-agency.sh

# ۲. نصب فهرست در Claude Code به‌صورت repo-local
./scripts/install.sh

# ۳. در Claude Code، داخل همین پوشه:
#    "از Agents Orchestrator بخواه جریان feature-development را اجرا کند."
```

اگر تازه به تیم اضافه شده‌اید، [`QUICKSTART.md`](QUICKSTART.md) را بخوانید —
ده دقیقه، از صفر تا اولین عامل در حال کار.

## سه لایه، سه مسئولیت

| لایه | پوشه | قاعده |
| --- | --- | --- |
| بالا دست | `upstream/` | **ویرایش نمی‌شود.** فقط با `scripts/sync-agents.sh --update-upstream` ارتقا می‌یابد. |
| مجموعهٔ منتخب | `agents/` | **کپی بایت‌به‌بایت.** فقط `scripts/sync-agents.sh` می‌نویسد. |
| هماهنگی | بقیهٔ پوشه‌ها | اینجا کار می‌کنیم. همه چیز قابل ویرایش است. |

این تفکیک عمدی است: ارتقای بالادست هرگز با تغییرات محلی درگیر نمی‌شود، و
`check-agency.sh` هر انحرافی را در همان ثانیه گزارش می‌دهد.

## اسکریپت‌ها

| دستور | کار |
| --- | --- |
| `./scripts/install.sh` | نصب فهرست در `.claude/agents/` (repo-local) |
| `./scripts/install.sh --user` | نصب اضافی و سراسری روی همین ماشین |
| `./scripts/install.sh --tool cursor --path .cursor/rules` | نصب برای ابزار دیگر (۱۷ ابزار پشتیبانی‌شده) |
| `./scripts/install.sh --check` | تأیید هم‌خوانی فهرست نصب‌شده |
| `./scripts/sync-agents.sh` | بازنشر `agents/` از `upstream/` طبق `registry.tsv` |
| `./scripts/sync-agents.sh --check` | تأیید نبود انحراف نسبت به بالادست |
| `./scripts/sync-agents.sh --update-upstream` | دریافت نسخهٔ پین‌شده از GitHub و بازنشر |
| `python3 scripts/gen-roster.py` | بازتولید جدول‌های `AGENTS.md` |
| `./scripts/check-agency.sh` | بررسی کامل: رجیستری، انحراف، لینک‌ها، نصب |

## یک عامل را چطور صدا بزنیم

```
از Frontend Developer استفاده کن و صفحهٔ ورود را بساز.
از Reality Checker بخواه این تغییر را قبل از انتشار تأیید کند.
از Agents Orchestrator بخواه جریان feature-development را کامل اجرا کند.
```

شناسهٔ انگلیسی عامل را بگویید؛ فهرست کامل با شناسه و «کی فعالش کنیم» در
[`AGENTS.md`](AGENTS.md) است.

## ده قاعدهٔ غیرقابل‌مذاکره

خلاصه‌ای از [`AGENCY.md`](AGENCY.md#۱۰-ده-قاعدهٔ-غیرقابل‌مذاکره):

1. عامل بالادست را ویرایش نکن؛ لایهٔ هماهنگی را ویرایش کن.
2. یک خروجی، یک مالک.
3. بدون معیار پذیرش، تسک باز نمی‌شود.
4. بدون شاهد اجرایی، «انجام شد» پذیرفته نیست.
5. حداکثر سه تلاش، بعد تشدید.
6. تصمیم مهم بدون ثبت دلیل، تصمیم نیست.
7. راز و کلید هرگز وارد مخزن نمی‌شود.
8. تغییر معماری بدون تأیید `software-architect` و در صورت لمس مرز اعتماد،
   `security-architect`، ممنوع است.
9. هر پروژهٔ فعال `STATUS.md` به‌روز دارد.
10. تغییر در سند آژانس نیاز به بازبینی اجرایی دارد.
