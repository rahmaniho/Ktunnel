## ۲. چه چیزی ساخته شد

### لایهٔ داده
- `SettingsRepository` (DataStore): انتخاب سرور، اتصال مجدد روی تغییر شبکه،
  بازگردانی پس از بوت، تأیید کارهای مخرب. **هیچ رازی اینجا نوشته نمی‌شود.**
- `ServerRepository`: تنها راه دسترسی صفحه‌ها به پیکربندی. `ServerSummary`
  **هیچ فیلدی برای کلید ندارد**، پس ViewModel نمی‌تواند کلید را به UI state یا
  لاگ ببرد.
- تحمل خرابی: فایل خوانده‌نشده شمرده می‌شود و نمایش داده می‌شود، نه اینکه بی‌صدا
  حذف شود.

### رابط کاربری
| صفحه | چه می‌کند |
| --- | --- |
| داشبورد | یک دکمهٔ اصلی، وضعیت صادقانه، آمار واقعی |
| سرورها | فهرست، انتخاب، حذف با تأیید، import فایل `.conf` |
| تنظیمات | چهار کلید واقعی + پاک‌سازی داده‌ها |
| عیب‌یابی | اجرای دستی آزمون، نتیجه در سه سطح |

### ناوبری
`Route` دست‌نویس به‌جای Navigation-Compose: چهار صفحه، بدون deep link، و یک
وابستگی کمتر برای pin کردن.
