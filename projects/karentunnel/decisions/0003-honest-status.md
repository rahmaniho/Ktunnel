# ADR-0003 — «متصل» فقط با سه شاهد هم‌زمان

## زمینه

اپ‌های VPN وضعیتی را از یک متغیر داخلی می‌خوانند. اگر آن متغیر بگوید UP، آیکون
سبز می‌شود — حتی اگر سیستم‌عامل تونل را کشته باشد یا دست‌دادن هرگز انجام نشده
باشد. کاربر فکر می‌کند محافظت دارد و ندارد.

## تصمیم

**انتخاب کردیم که** ادعای «متصل» فقط وقتی مطرح شود که هر سه شرط برقرار باشند:

1. backend گزارش UP بدهد
2. `ConnectivityManager` واقعاً یک شبکهٔ VPN ببیند
3. دست‌دادن تازه باشد (کمتر از ۱۸۰ ثانیه)

اگر شرط ۳ برقرار نباشد، وضعیت `Degraded` است: «متصل، بدون تأیید»، رنگ کهربایی،
هرگز سبز.

`stateForFailure` از نظر نوع، **نمی‌تواند** `Connected` برگرداند. تست
`failure never maps to connected` این را روی همهٔ انواع خطا بررسی می‌کند.

## گزینه‌های ردشده

| گزینه | چرا رد شد |
| --- | --- |
| فقط وضعیت backend | همان باگ رایج؛ backend می‌تواند UP بگوید و تونل مرده باشد. |
| فقط `ConnectivityManager` | VPN دیگری هم می‌تواند شبکهٔ VPN بسازد. |
| `ping` به اینترنت | iframe زمان‌بر، نویزی، و نتیجه‌اش مبهم است (آیا ICMP مسدود شده یا تونل خراب است؟). |
| سبز کردن بعد از timeout مشخص | همان دروغ، با تأخیر. |

## پیامدها

- حالت `Degraded` بیشتر دیده می‌شود و ممکن است کاربر را نگران کند. این درست است:
  نگرانی صادقانه بهتر از اطمینان دروغین است.
- یک وضعیت بیشتر در ماشین حالت و در UI.
